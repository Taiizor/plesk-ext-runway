# Runway — design and contracts

Runway is a Plesk Obsidian extension that runs compiled or long-running applications (Go, Rust,
Bun, Java, .NET, Python, Ruby, PHP, or any prebuilt binary) per domain **without Docker**:
toolchains are installed by the administrator, applications are built as the subscription's
system user and run as hardened systemd services, nginx proxies the domain to them.

This document is the single source of truth for the project. Every agent working on Runway
reads it first. Decisions here are final unless this file is changed.

## 1. Decisions

| Topic | Decision |
|---|---|
| Name / id | **Runway**, extension id `runway`, PHP class prefix `Modules_Runway_`, GitHub repo `plesk-ext-runway` (public, MIT) |
| Shape | **One extension**, runtime-agnostic core + runtime adapters |
| Platforms | **Linux only** (`<os>unix</os>`): Ubuntu 22.04/24.04, Debian 12, AlmaLinux/RHEL 9 (python3 + systemd required). Windows is a possible later adapter (IIS HttpPlatformHandler); the PHP layer keeps a `ProcessManager` abstraction for it |
| UI | **React + Plesk UI Library** via `@plesk/plesk-ext-sdk` (v0.9, React 18, ui-library 3.46, react-router 7), built with **Bun** (`bunx plesk-ext-sdk build`). PHP is a JSON API only |
| Runtimes in 1.0 | `go`, `rust`, `bun`, `java`, `dotnet`, `python`, `ruby`, `php`, `binary` (no Node.js: Plesk has its own Node.js Toolkit) |
| Base | Evolves from the author's earlier private Go & Rust Toolkit 1.0.0 (root helper, PHP model, hooks, systemd/nginx integration, tests). Nothing is rewritten for its own sake; it is renamed and extended |
| Plesk version | `plesk_min_version` 18.0.55 (callSbin stdin). Developed and tested on 18.0.82 |

## 3. Naming on the server

| Item | Value |
|---|---|
| Helper | `/usr/local/psa/admin/sbin/modules/runway/runway-helper`, stable copy `/opt/runway/bin/runway-helper` |
| Toolchains | `/opt/runway/<runtime>/...` (e.g. `/opt/runway/go/1.27.4`, `/opt/runway/rust/{rustup,cargo}`, `/opt/runway/bun/1.3.2`, `/opt/runway/java/21.0.5`, `/opt/runway/dotnet` (shared root, versions inside), `/opt/runway/python/3.13.1` (uv-managed), `/opt/runway/uv/uv`) |
| State | `/var/lib/runway/{apps,jobs,locks,cache}` (root 0700) |
| Env files | `/etc/runway/env/<domainId>.env` (root 0600) |
| Units | `runway-app-<id>.service`, `runway-deploy-<id>.service`, `runway-deploy-<id>.path`, transient `runway-job-admin.service` and `runway-redeploy-<id>` (timer that restarts a deployment when a trigger file changed while no time was left) |
| Sockets | `/run/runway/<id>/app.sock` (dir `sysuser:psaserv` 2750, created by the helper as root; at boot by `systemd-tmpfiles` from `/etc/tmpfiles.d/runway-<id>.conf`, plus `runway.conf` for `/run/runway` itself) |
| Per-user caches | `~/.runway/` in the subscription (GOPATH, GOCACHE, CARGO_HOME, BUN_INSTALL cache, Maven/Gradle caches, NUGET_PACKAGES, pip/uv cache, GEM_HOME, Composer cache) |
| App env vars | tcp and none: `PORT`, `HOST=127.0.0.1`, `LISTEN_ADDR`; unix: `RUNWAY_SOCKET` only (no `PORT`/`HOST`/`LISTEN_ADDR`; the port stays reserved in the state); always `RUNWAY_LISTEN` (tcp\|unix\|none), `RUNWAY_APP_ROOT`, `RUNWAY_START_CMD` (internal). Reserved for users: these plus `HOME`, `USER`, `LOGNAME`; refused: `LD_PRELOAD`, `LD_AUDIT`, `GCONV_PATH`, `GLIBC_TUNABLES` ("put it in the start command") |
| Trigger files | `<app root>/tmp/deploy.txt` (build + restart), `<app root>/tmp/restart.txt` (restart) |
| Domain settings keys | `runwayApp` (JSON config without env), `runwayLimits` (admin-only limits) |
| Permission | `manage_runway_apps` (plan/subscription) |
| Scheduled task | `reconcile.php` every 10 minutes |

## 4. Architecture (unchanged principles from the base)

- **PHP (psaadm)** validates input, stores the per-domain config in domain settings, and calls the
  root helper via `pm_ApiCli::callSbin('runway-helper', [command], RESULT_FULL, [], <json on stdin>)`.
  Secrets (env vars) live only in the helper's root-only state.
- **Helper (root, python3 ≥ 3.8 stdlib only)** re-validates everything, renders units/env files,
  drives systemd, installs toolchains (background job unit), runs builds in `runway-deploy-<id>.service`
  as the system user (dropped privileges, deadline, limits), checks listener ownership.
  Anything that touches customer files runs in a forked child that became the customer, with a
  deadline and no inherited descriptors.
- **nginx**: `pm_Hook_WebServer` (both `getDomainNginxConfig` and `getDomainNginxProxyConfig`)
  emits one regex location (Docker-proxy-rules technique), with negative lookahead for Plesk
  statistics paths, ACME and user static paths. Apache snippet mirrors it with IfModule guards.
- **Reconcile**: every relevant Plesk event + scheduled task converge services with Plesk
  (delete, rename, sysuser change, suspend/activate incl. customer/reseller status).
- **Security invariants** (keep them; they were verified by review): no customer text in unit
  files (`ExecStart=/bin/bash -c ${RUNWAY_START_CMD}` from the env file), env file quoting rules,
  **no root-privileged Exec line (`+`/`!`) in any app unit** (every Exec line gets the customer's
  environment file; root work such as the socket directory is done by the helper in
  `prepare_start()` and by systemd-tmpfiles), loader variables (`LD_PRELOAD`, `LD_AUDIT`,
  `GCONV_PATH`, `GLIBC_TUNABLES`) refused in PHP and the helper, `SocketBindAllow/Deny`,
  listener-uid check (TCP) / socket check with containment (unix: anything but the user's own
  socket is removed as root through a directory descriptor, the unit stopped and disabled, the
  state marked `tampered`), build limits (always TasksMax), resource limits of `call_as_user`
  children (RLIMIT_AS 512 MiB, RLIMIT_FSIZE 64 MiB or 2 GB for fetch, RLIMIT_CPU = deadline + 5 s)
  and capped directory listings, suspended/disabled apply stops the deploy unit, deploy re-checks
  state before restart, bounded log reads, `call_as_user` timeout + fd hygiene, Reconcile ignores
  helper states younger than 5 min, `remove()` reconfigures nginx before freeing the port.

## 5. Runtime adapters

### 5.1 Helper side (`sbin/runway-helper`, module-level registry)

Each runtime is a class with a common interface; the registry is `RUNTIMES = {"go": GoRuntime(), ...}`.

```python
class Runtime:
    key = "go"            # id used everywhere (config, API, UI)
    label = "Go"
    toolchain = "managed" # "managed": Runway installs versions under /opt/runway/<key>/<version>
                          # "detected": versions provided by the system/Plesk are discovered (php, ruby)
                          # "none": no toolchain (binary)
    version_re = r"..."   # accepted version/channel strings
    def list_installed(self): ...          # [{"id": "1.27.4", "label": "Go 1.27.4", "path": "..."}]
    def list_available(self, force=False): # [{"id": "...", "label": "..."}], network, cached 6h in /var/lib/runway/cache
    def install(self, version, log): ...   # runs inside the admin job unit; verifies checksums when the source offers them
    def remove(self, version): ...
    def update(self, version, log): ...    # channels only (rust stable, bun latest, ...) else HelperError
    def env(self, home, version): ...      # {"PATH": [dirs...], "VAR": "value"}: toolchain bins + per-user caches under ~/.runway
    def inspect(self, app_dir): ...        # RUNS AS THE USER (called inside call_as_user): detection dict or None
    def defaults(self, inspect): ...       # {"build_cmd": "...", "start_cmd": "..."}
    def sample(self, app_dir, listen): ... # RUNS AS THE USER: writes a minimal HTTP app (uses RUNWAY_SOCKET or PORT)
    def build_deps(self): ...              # ["cc", "pkg-config", ...] tools that should exist for builds (status only)
    def prepare_start(self, state, pw): ...# root, before every start of the app unit (PHP: Octane's .runway/Caddyfile, written as the user)
    def may_use(self, configured, build):  # True when a channel id (Java "21", Python "3.13", .NET "10.0") may resolve to that build
```

Metadata exported to PHP/UI by the `runtimes` command (so the frontend has one source of truth):
`{key, label, toolchain, version_re, hint, docs_url, default_listen, supports_build, install_help,
detected_only, unix_toolchain_re, hint_key, install_help_key}`. `hint_key`/`install_help_key`
(`Runtime.<key>.hint`, `Runtime.<key>.installHelp`, `""` without a text) name the frontend locale
keys of the English `hint`/`install_help`, which stay the fallback. `toolchain` is the kind (`managed|detected|none`),
`detected_only` = `toolchain == "detected"`, `unix_toolchain_re` (Python regex, `""` = every
toolchain) names the toolchains whose default start command can listen on a Unix socket (PHP:
`^frankenphp-`, `php -S` is TCP only). `version_re` per runtime: go
`^1\.\d{1,3}(\.\d{1,3})?((rc|beta)\d{1,2})?$`, rust
`^(stable|beta|nightly(-\d{4}-\d{2}-\d{2})?|1\.\d{1,3}(\.\d{1,3})?)$`, bun
`^(latest|\d+\.\d+\.\d+)$`, java `^\d{1,2}(\.\d+){0,5}(\+\d+)?$`, dotnet `^\d+\.\d+(\.\d{3})?$`,
python `^3\.\d{1,2}(\.\d{1,2})?$`, ruby `^(system|\d+\.\d+\.\d+)$`, php
`^(system|plesk-\d+\.\d+|frankenphp-\d+\.\d+\.\d+)$`, binary `""` (no toolchain).

| binary | none | n/a | n/a | PATH only | executable files in app root | none / `./app` |

Rules for every adapter:
- Downloads only over https from the official source; verify the checksum the source publishes
  (SHA-256/512 files or JSON fields). Extract with the safe tar/zip routine (no absolute paths,
  no `..`, no devices). `chmod_public` the tree (root-owned, world-readable, not writable).
- `env()` must keep all caches inside the subscription (`~/.runway/...`) so they count against
  the customer's quota and are deletable by the customer.
- `inspect()` and `sample()` run as the customer (via `call_as_user`); they must not follow
  symlinks when reading (`_read_small`) and must cap sizes.
- `list_available()` failures must not break the UI: return `[]` plus an `error` string.

### 5.3 Listen modes and app modes

- `listen`: `tcp` (PORT, HOST, LISTEN_ADDR), `unix` (RUNWAY_SOCKET only; the unit denies every TCP
  bind), `none` (worker: no proxy, no listener check; PORT etc. are still set).
- `mode`: `web` (whole domain proxied), `path` (only `mount_path` prefix proxied, e.g. `/api`;
  nginx: `location ~ ^/api(/|$)`; Apache: `ProxyPass /api ...`), `worker` (= listen none).
- `static_paths`: up to 20 URL prefixes (`^/[A-Za-z0-9._~-]+(/[A-Za-z0-9._~-]+)*$`) excluded from
  the proxy regex so nginx/Apache serve them from the document root (SPA assets).
- `health_path`: optional path; `app-status` performs one GET (2 s timeout, Host = domain) and
  reports `healthy|unhealthy|unknown`. No automatic restart in 1.0.

## 6. HTTP API (PHP `ApiController`, all JSON, `index.php/api/<action>`)

Conventions: responses are `{"status": "success", "data": ...}` or
`{"status": "error", "errors": ["..."]}` (SDK convention; `ServerList`/`ServerForm` helpers may be
used for lists/forms). Validation errors are keyed by field: `{"status": "error", "errors":
{"field": ["msg"]}}`. Responses always use HTTP 200. Mutations are POST with a JSON body
(`X-Forgery-Protection-Token` is sent by the api client). Every domain action resolves the domain
from `site_id` (query or body) through `Modules_Runway_Access::domainFromRequest` (admin, or
customer with permission and access). Admin-only actions check `Access::requireAdmin()`.

| Action | Method | Who | Data |
|---|---|---|---|
| `api/context` | GET | all | `{isAdmin, locale, runtimes:[meta...], urls:{api,...}, limits:{maxStaticPaths}}` |

## 7. Helper command contract (`runway-helper <command>`, JSON payload on stdin)

Every answer is one JSON object: `{"ok": true, ...result}` or `{"ok": false, "error": "...",
"code"?: "..."}` (exit code 1). `code` is a machine-readable reason the panel maps to a form field:
`not_empty` and `unix_unsupported` (app-sample). Errors raised inside `call_as_user` children keep
their code.

| Command | Payload | Result |
|---|---|---|
| `runtimes` | — | `{runtimes:[meta...]}` (§5.1) |

Codes for translation: `listener_code` ∈ `ok, none, foreign, tampered, socket_symlink,
socket_not_socket, socket_owner, worker`, `health_code` ∈ `no_path, not_listening, failed, no_http,
http` (params as in the English detail); job statuses carry `title_key` (`install, update,
build_deps, deploy_build, deploy_restart, deploy_fetch`, and for a deployment of a stopped application
`deploy_build_only`, `deploy_restart_skipped`, `deploy_fetch_only`, chosen when the job starts) +
`title_params`. The panel translates
them (`Domain.status.listenerDetail.*`, `Domain.status.healthDetail.*`, `Common.jobTitle.*`) and
shows the English text when a key is missing. Helper error messages stay English.

Deploy job: `TimeoutStartSec = min(1800, build_timeout) + build_timeout + 300`; SIGTERM (timeout,
disabled/suspended app) marks the job failed with the reason. A trigger file touched while the
job runs starts another round after it (at most three; when no time is left, a transient
`runway-redeploy-<id>` timer starts the deploy unit again a minute later).

Child processes of `call_as_user` have rlimits (address space 512 MiB, file size 64 MiB, or
4 × 500 MB for fetch, CPU = deadline + 5 s). Directory listings use `os.scandir` with caps:
`app-inspect`/`app-page` count at most 10 000 entries (`entry_count`, `more: true` above) and
return the first 80 sorted names; adapters read at most 500 (Java) or 2000 (.NET, binary) names.

Test-only switches (root-owned regular files): `/etc/runway/allow-insecure-fetch` lets fetch use
`http://` and private addresses (reported by `info` as `fetch_insecure`, PHP then accepts
`http://` URLs); `/var/lib/runway/pause-reconcile` makes `apps-list` report
`reconcile_paused: true` while the file is younger than one hour, and `Modules_Runway_Reconcile`
then changes nothing (tests/helper-smoke.sh uses the fake domain id 999).

Fetch security: https only, the download runs as the customer, every address of the host must be
public; the connection is made to exactly the checked address (pinned lookup through a custom
`http.client` connection factory, TLS still verifies the host name), redirects are re-checked,
proxies are not used, 500 MB cap.

## 8. Frontend (React, `src/frontend`)

Routes (`extension.config.js`): `overview` (default), `toolchains`, `settings`, `domain` (reads
`site_id` from the query string). Components use `@plesk/plesk-ext-sdk` exports (ui-library:
`Section`, `Grid`, `Form*`, `Button`, `Toolbar`, `List`, `Tabs`, `Drawer`, `Alert`, `Status`/`Label`,
`ProgressBar`, `Text`, `Heading`, `Toaster` via `withStatusMessages`, `Translate`). Pages:

- **Overview**: toolbar (Toolchains, Settings for admins), list of apps/domains with status
  labels and a link to the domain page; empty state explains the 3 steps.
- **Toolchains**: tabs per runtime; each tab = installed list (version, used by, remove/update)
  + install control (select for managed, instructions for detected); build dependencies card;
  job panel with live log (poll every 2 s while busy).
- **Settings**: form.
- **Domain**: status card (state label, facts, Start/Stop/Restart/Build & restart buttons; Start
  and Restart are disabled while a deployment runs, a stopped app shows "stays stopped until you
  start it", a tampered app an explanation of the containment),
  project card (detection, "Create sample app", "Fetch binary from URL" drawers), settings form
  with progressive disclosure (basic: enabled, runtime, toolchain, app root, listen/mode; "Advanced"
  section: commands, env, mount path, static paths, health path, triggers, limits (admin)),
  logs card (tabs app/deploy, auto-refresh), help card, danger zone (remove).
- Polling pauses when `document.hidden` except for 2 min after a user action; status updates
  every 6 s (2 s while a job runs). Confirmations use ui-library `Dialog`, never `window.confirm`.
- Translations: `src/plib/resources/locales/*.php` key `'app' => [...]` nested per component
  (`Overview.title`, ...). Every Plesk locale (en-US is the reference, tr-TR hand-written, the
  other 30 machine-translated and reviewed). Texts produced by the helper are translated through
  their keys (`hint_key`, `title_key`, `listener_code`, `health_code`) with the English text as
  fallback; the API client's own errors use `Common.requestFailed`/`Common.unexpectedResponse`.

## 9. CLI (`pm_Hook_ApiCli`, `plesk ext runway ...`)

`--list`, `--status <domain>`, `--start|--stop|--restart|--deploy <domain> [-no-wait]` (`--stop`
persists until `--start`/`--restart`; `--deploy` builds a stopped application without starting it),
`--enable|--disable <domain>`, `--toolchains`, `--install-toolchain <runtime> <version> [-no-wait]`,
`--reconcile`. `<domain>` is a name or a domain id. Exit codes: 0 success, 1 failure, 2 usage
error (unknown command, domain or runtime). Admin context.

## 10. Testing and release

- Local: `plesk/plesk` container (`scripts/plesk-dev.sh`), `tests/helper-smoke.sh` (root helper,
  fake domain id 999 with the reconcile pause flag), `tests/api-smoke.sh` (login link → cookies →
  API calls), `tests/customer-smoke.sh` (customer `cust1` with and without the permission),
  `tests/runtime-e2e.sh` (sample app per runtime and listen mode through the API and nginx, path
  mode, static paths, triggers, worker, suspension, CLI, WebSockets through nginx and Apache,
  optional Laravel Octane), browser check of each page.
- CI (`.github/workflows/ci.yml`): lint (pyflakes, Python 3.8 grammar check of the helper,
  locales, bun build, `build.py --check`, `php -l` in `php:7.4-cli` and `php:8.2-cli`), build
  (bun + `build.py --strict`, zip artifact), e2e in the Plesk container through
  `.github/scripts/plesk-e2e.sh` (install zip, subscription, customer `cust1` when the license
  allows it, install Go, then helper-smoke, api-smoke, customer-smoke (skipped without the customer)
  and the Go part of runtime-e2e, `RUNWAY_E2E_RUNTIMES=go`, about 2 minutes); the full runtime
  matrix runs locally. Pushes that only change documentation skip CI; pull requests always run
  it (the required checks of `develop` must start). CodeQL (`codeql.yml`) analyses the helper,
  the frontend and the workflows. Release (`release.yml`): tag `v*` → version gate (tag =
  `src/meta.xml`) → CI → GitHub Release with the tested zip, SHA256SUMS and generated notes
  (CHANGELOG section + install + checksums + "What's Changed" from the labelled pull requests,
  docs/RELEASING.md); "Run workflow" rehearses it without publishing.
- Packaging: `build.py` runs `bun run build` (= `plesk-ext-sdk build`) unless `--no-frontend`,
  then zips `src/` without `frontend/`; LF normalization and Unix modes as in the base. The
  packaged `htdocs/index.php` loads `dist/main.js?v=<version>-<release>.<sha256 prefix>` (cache
  buster: Plesk serves the bundle without cache headers); `--verify` checks it.

## 11. Non-goals for 1.0

Windows, zero-downtime deploys, multiple processes per app, resource graphs, automatic restart on
failed health checks, Plesk catalog submission.
